Alata projects are generated by the `alata-new` scaffolder, which copies a complete, runnable project template — application code, configuration, migrations, and tooling — into a new directory. This page takes you from an empty folder to a responding `/health` endpoint.

## Prerequisites

- **Python 3.12 or newer** — the framework requires `python >= 3.12`.
- **[uv](https://docs.astral.sh/uv/)** — the recommended package manager. The generated `Makefile` and `pyproject.toml` assume it, though plain `pip` works too.
- **PostgreSQL (recommended)** — Alata's database layer is PostgreSQL-first. MySQL 8.0+ is also supported, and SQLite works for lightweight use; both install as optional extras (`alata[mysql]`, `alata[sqlite]`).
- **Redis** — the default queue and cache backend.

<Callout type="info">
Alata is not published on PyPI. It installs from the Git repository — the scaffolded `pyproject.toml` includes a commented `[tool.uv.sources]` entry you enable in the steps below.
</Callout>

## Creating a project

<Steps>
<Step>
### Run the scaffolder

The `alata-new` console script ships with the `alata` package. The easiest way to run it without installing anything permanently is `uvx`:

```bash
uvx --from git+ssh://git@github.com/JoBinsJP/alata-core.git alata-new new my-app
```

If you already have `alata` installed in an environment, just run:

```bash
alata-new new my-app
```

Pass `.` instead of a name to scaffold into the current directory. The scaffolder copies the project template and stamps your project name into `pyproject.toml` and `README.md`.
</Step>

<Step>
### Look at what was generated

The scaffolder produces a complete application skeleton:

```
my-app/
├── alata                 # console entry point (./alata <command>)
├── main.py               # uvicorn entry point (main:app)
├── Makefile              # common developer commands
├── pyproject.toml
├── .env.example
├── app/                  # your application code
├── bootstrap/            # the application kernel
├── config/               # configuration modules
├── database/migrations/  # starter migrations (users, job batches, failed jobs)
├── routes/               # route definitions
├── storage/              # logs and framework runtime files
└── tests/                # a passing starter test
```

The [directory structure page](/docs/getting-started/directory-structure) walks through every directory in detail.
</Step>

<Step>
### Point the project at the framework

Open `pyproject.toml` and uncomment the `[tool.uv.sources]` block so uv knows where to fetch `alata` from:

```toml title="pyproject.toml"
[tool.uv.sources]
alata = { git = "ssh://git@github.com/JoBinsJP/alata-core.git", tag = "v0.6.0" }
```

Pin the tag you want to build against. This requires SSH access to the repository; adjust the host alias to match your `~/.ssh/config` if needed.
</Step>

<Step>
### Install dependencies

```bash
make install
```

This runs `uv sync`, which creates a `.venv` and installs everything — the framework, uvicorn, and the dev dependency group (pytest, httpx).

<Callout type="info">
You never need to activate the virtualenv to use the CLI. The `./alata` script detects `.venv/bin/python` and re-executes itself with it automatically.
</Callout>
</Step>

<Step>
### Configure your environment

```bash
cp .env.example .env
```

Open `.env` and set your PostgreSQL credentials (`DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`) and `REDIS_URL`. The file also sets `APP_ENV=local`, which the kernel reads to [resolve the environment](/docs/getting-started/configuration#env-files-and-environment-detection) at boot.
</Step>

<Step>
### Run the starter migrations

```bash
./alata migrate
```

The template ships three migrations: a `users` table, plus the `job_batches` and `failed_jobs` tables that the [queue system](/docs/digging-deeper/queues) uses. Check the result with:

```bash
./alata migrate:status
```
</Step>

<Step>
### Boot the development server

```bash
./alata serve
```

`./alata serve` starts a uvicorn server on `127.0.0.1:8000` with hot reload enabled — pass `--host`, `--port`, `--workers`, or `--no-reload` to tune it.

You can also start uvicorn yourself against the ASGI entry point:

```bash
uvicorn bootstrap.app:app --reload
# or: python main.py
```

All of these load the same application kernel.
</Step>

<Step>
### Verify it works

The framework mounts health endpoints automatically — no route registration needed:

```bash
curl http://127.0.0.1:8001/health
# {"status": "ok"}

curl http://127.0.0.1:8001/health/db
# {"status": "ok", "connections": {"default": "ok"}}
```

And the template's welcome route:

```bash
curl http://127.0.0.1:8001/api/v1/
# {"message": "Welcome to Alata Framework!"}
```

Finally, run the starter test suite:

```bash
make test
```
</Step>
</Steps>
